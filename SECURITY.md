# Security policy

Do not report credentials, private repository contents, employee/customer data, live Apps Script URLs, IDs, or exploit details in a public issue.

Use GitHub private vulnerability reporting after it is enabled, or an approved internal Copado security channel. Include the affected skill/version, impact, reproduction using fictional data, and suggested mitigation.

Maintainers should acknowledge reports privately, rotate any exposed credential immediately, remove sensitive history using the approved incident process, assess released archives/checksums, and publish a patched namespaced release.

Supported security fixes target the latest released version of each skill. Older versions should upgrade through their documented pinned-release process.
